   because 3 agents shared one checkout. **Decision:** every build agent runs with
   `isolation: 'worktree'` and commits to its own branch; orchestrator merges sequentially
   into main with a gate (typecheck/test/build) after each merge. No two agents touch main
   directly.

   **Decision:** leave them open, do not assign build agents to them, and at the end of the
   run summarize what a human still needs to verify. They are not "incomplete work" on my
   part.

4. **[06:55] Build order = dependency + file-surface clustering.** Tasks that touch the same
   files are sequenced under ONE agent (not parallelized) to avoid merge conflicts even with
   worktrees (cleaner history). Independent surfaces run in parallel up to 3 at a time.

5. **[07:06] Stale-branch drift caught at first merge.** The primary checkout was sitting on
   a leftover local branch `agent/operator-split-pane` (from a prior session), not `main`. My
   W1-C `--no-ff` merge landed there instead of main. Caught it immediately (main head hadn't
   moved). **Resolution:** the merge content was correct; fast-forwarded `main` to the merge
   commit (4cc6244), checked out main, deleted the stale branch. No work lost; the two running
   W1 agents were in their own worktrees and untouched. **Process fix going forward:** verify
   `git branch --show-current` == main BEFORE every merge.

6. **[07:20] Stale-branch drift RECURRED — now understood + guarded.** Same symptom at the
   W2-D merge: primary checkout was on a leftover `agent/*` branch, merge landed there. ROOT
   CAUSE: the worktree-isolation machinery leaves an `agent/<slug>` branch checked out in the
   PRIMARY repo (separate from the `worktree-agent-<id>` branches inside .claude/worktrees/).
   Each merge content was correct; fixed by `git branch -f main <merge>` + checkout + delete
   stale branch. **STANDING GUARD adopted:** run `git checkout main` immediately before EVERY
   merge, regardless of what `--show-current` reports. No work was ever lost (agents commit to
   their own worktree branches); this only affected where MY merge commit landed.
